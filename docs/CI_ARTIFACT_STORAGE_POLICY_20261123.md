# iEventPlux CI artifact and shared VPS storage policy (23 November 2026)

The production-build GitHub Actions job now packages its already smoke-tested Next standalone output, public assets and static assets into a source-light tarball. The candidate contains `SOURCE_SHA` (the exact GitHub commit) and `SHA256SUMS`, verified before upload. GitHub retains it for two days. **CI does not deploy or restart the live service.** The archive is not a migration, payment certification, or authorization to enable merchandise flags.

Before a separate operator-approved release: inspect current origin/main and PR heads, deployment health, `df -h /`, running builds and process executable paths, Nginx/PM2/systemd references, current symlinks, live uploads and transaction state. Do not start a heavy VPS build at >=90% usage or below approximately 30 GB free. Download the exact approved SHA's candidate, verify SHA256 and source SHA, and extract to a new isolated path; never overwrite the active checkout. Preserve all secrets and durable uploads outside artifacts. Run the target runtime with correct external environment and durable data mounts, staging authorization/security and health checks, and verify financial reconciliation before any transaction-service cutover. Keep the active release and one verified rollback; only delete confirmed inactive generated artifacts after process/path and ownership checks. Never delete audit logs, databases, media, secrets, unpushed changes, or other projects' files.

Merchandise charging and collection stay independently disabled until provider settlement/refund QA, actual smartphone camera QA, schema rehearsal and verified pre-migration backup, and an explicit safe rollout. The candidate is for review/testing, not an automatic production deployment.
