**Release discipline:** maintain both web and native platforms in each planning cycle. Real business operations matter more than merely improving screen styling; UI parity is not API parity until workflows are actually usable and tested. Do not confuse merged code, passing CI, deployed binaries, and tested customer functionality.

## Next release milestones

1. **Continuous web + mobile parity:** carry each feature across both fronts and test the whole workflow (not just styling). Restore responsive web layouts, real API data, accessible dialogs, honest states and automatic data refresh after mutation; make sure the current live portal receives verified deployments.
2. **Real creator content:** finish moderated video intake, scan/transcode/publish with reliable browser and native playback; add native creator submission, recording and review UX, cross-platform comments/reporting and creator profiles. Never mark quarantined uploads READY without review.
3. **Production-ready live communication:** physical Android/iOS device call tests, scalable room admission, real TURN/SFU and genuine broadcast delivery, event interaction/chat/screen-share, opt-in permissions and protected paid-event access.
4. **Safe transaction platform:** independent store checkout, provider-confirmed settlement, stock reservation, seller fulfilment/delivery/POD/returns and reconciliation; paid fan voting only after immutable verified settlements, fraud controls and regulatory review.
5. **World-scale experience:** personalized and accessible 24/7 feeds, event social graph, live shopping, moderation, ad transparency, full international policy, privacy and performance safeguards, and validated infrastructure load/operating costs.

## Current change's acceptance checks

- Creator Media must be a native WEB organizer section (not a redirection to the mobile app), role-filtered for the same OWNER/ADMIN/EVENT_MANAGER media permissions as the backend.
- Org switching must not leak a prior org's clip queue. Camera and rights controls are honest, two separate consent confirmations required, and file type/size checked before submission.
- After a successful upload, the queue refreshes without requiring the user to reload the whole page; status remains PROCESSING, not a fake playable video.
- Public Reels cards only mount an HTML `<video>` for approved same-origin MP4 paths; otherwise actual event artwork remains and is labelled Preview. Only the visible and foreground clip may play and autoplay is muted, with explicit sound/pause controls.
- Web lint/typecheck, full CI/integration smoke, production bundle and live deployment verification precede public readiness claims. Both mobile APK and web must be certified separately.
