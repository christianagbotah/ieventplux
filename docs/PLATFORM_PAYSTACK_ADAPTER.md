# Paystack checkout adapter contracts (sandbox, not wired)
Reference: https://paystack.com/docs/api/transaction/ and https://paystack.com/docs/payments/split-payments/ and https://paystack.com/docs/payments/webhooks/.
Constructs direct vs single-subaccount split request from a persisted server-resolved intent and matching test recipient. Accepts only positive purchases; zero-commission splits are gated pending provider evidence. Platform bears processing fees in this initial contract; not a final commercial policy. Verification checks test domain, successful status, exact reference, amount, currency and intended subaccount. Checkout URL is constrained to the official HTTPS origin. Legacy raw-byte HMAC verifier is test-only; new signing-secret format must be implemented separately. The module has no provider network calls, public endpoint, ledger or fulfillment changes. A confirmed collection does not prove split allocation or settlement. Real sandbox responses, provider capabilities, durable attempt orchestration, idempotent callbacks and allocation reconciliation remain certification gates. Do not enable live credentials or replace existing Hubtel checkout.
